A1.1 Source: one CSV per station/day with station,date,hour,pm25,pm10,no2,temperature. Problems: blank and NA values; negative readings; impossible values above 999; duplicate station/date/hour; Fahrenheit instead of Celsius; wrong date/hour; missing/extra columns; inconsistent station spelling; wrong encoding.
A1.2 SQLite: stations(station_id INTEGER PRIMARY KEY, station_name TEXT UNIQUE NOT NULL). readings(reading_id INTEGER PRIMARY KEY, station_id INTEGER REFERENCES stations, reading_date TEXT, hour INTEGER, pm25 REAL, pm10 REAL, no2 REAL, temperature_c REAL, UNIQUE(station_id,reading_date,hour)). CSV station maps to station_name; date/hour and pollutant columns map directly; temperature is converted to Celsius.
A1.3 Examples: station monthly average uses WHERE + AVG; daily station means use GROUP BY station,date; worst readings use ORDER BY pm25 DESC LIMIT. CSV requires scanning/grouping files each time; SQLite supports repeatable queries and indexes. Loading all CSVs into pandas for each question costs O(n) scan and O(n) RAM; indexed SQLite lookup is about O(log n) plus matching rows, with data stored on disk.
